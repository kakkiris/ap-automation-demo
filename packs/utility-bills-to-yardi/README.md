# Utility bills to Yardi

The utility system for the Industrial AP department. A bill lands, gets read and checked, and becomes a Yardi row whose description carries the account number; every meter keeps a dated history of who held its account, because account numbers change with every turnover; and every meter, every month, is checked against the rent roll so the portfolio can see which bills are paid, unpaid, not yet billed, or a bill-back, with the shut-off risk on top. It is one code module with one in-memory store, one seed, and one reset. The August run through Yardi import confirmed is its end-to-end flow, covered by the Playwright spec in e2e/.

The sidebar shows it as three modules under Industrial AP: Utility bills to Yardi (Capture this month's bills, Match bills to meters), Meter register (Every meter and its account, One meter's history), and Paid-or-not reconciliation (Which bills are paid, One property month by month, Confirm which account a payment matched, Payments without a meter, Bill-backs transfers and calls, Files and notes produced, The tracker as kept today). The three route prefixes read and write the same store and share the same reset route, so resetting any one of them resets all three. Their descriptors and the shared href helper, utilRoutes, live in module.ts; the screens in ui/ link to each other only through that helper.

To regenerate the seed, run `npm run seed` from the repo root; it writes data/seed.json, the canned bill extractions, and the provider account list and site visit CSVs that the fill-the-master mechanisms read. Then run `npm run sample-bills` to render the five sample bill PDFs into public/sample-bills from that seed, since the drop zone on Capture this month's bills only accepts those file names. Unit tests run with `npx vitest run packs/utility-bills-to-yardi`; the August flow runs with `E2E_BASE_URL=http://localhost:3000 npx playwright test packs/utility-bills-to-yardi` against a running dev server.
