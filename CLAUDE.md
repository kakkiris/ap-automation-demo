# AP demo suite

One Next.js app hosting Accounts Payable demo packs as modules for two departments, Family Office AP (`family-office-ap`) and Industrial AP (`industrial-ap`). Navigation is a left sidebar grouped by department and module (`components/shell/`), driven by `lib/registry.ts`.

## Commands

`npm install`, `npm run dev`, `npm test`, `npm run seed` (rewrites the utility seed in data/, canned extractions, the provider account list, and the site visit results; other modules regenerate with `npx tsx packs/<slug>/seed/generate.ts`), `npm run sample-bills` (rewrites public/sample-bills), `npm run e2e` (Playwright: e2e/shell.spec.ts plus every module's specs, reusing a running dev server), `npm run reset` (posts to every module's reset route), `npm run check:markers`, `npm run check:names`, `npm run check:figures`, `npm run check:dashes`, `npm run build`.

## Rules for every file

- Synthetic data only. No real company, person, tenant, address, account number, meter number, or amount anywhere. Every provider, town, vendor, owner, and tenant is invented, and so is everything attached to them.
- Markers: account numbers start with 99 (99 plus eight digits), meter ids start with M9 (M9 plus six digits) and physical meter numbers with M9 (M9 plus eight digits), vendor codes start with v99, property codes with 0999, GL codes with 9. Fictional names come only from the lists in the seed generators. `npm run check:markers` enforces all of it, plus each module's own rules from its markers.json.
- People appear only as roles: the AP operator, the accounting lead.
- Plain language in the client's words on every client-facing string: meter, house meter, shared meter, account number, rent roll, vacant unit, bill-back, provider. Never "model", "deterministic", "pipeline", or "API" on a client-facing surface.
- No em dashes anywhere.
- Deterministic code for money math, matching, vacancy logic, and status assignment. The utility pack makes no model calls; its extraction is `extractBillFields(billRef)` over `data/canned-extractions.json`. Other packs limit model steps to reading documents and returning checked fields.
- Meter is the permanent key. Never key anything on account number.
- No auth, no database. `data/seed.json` loads into an in-memory store at boot; reset re-seeds.
- Leak guard: a list of real names that must never appear (companies, people, places, systems) is kept outside the repo (`../forbidden-names.txt` or `FORBIDDEN_NAMES_FILE`) and scanned over the whole repo by `npm run check:names`; a list of real-world figures heard in discovery (`../forbidden-figures.txt` or `FORBIDDEN_FIGURES_FILE`) is scanned over client-facing sources only (app, components, packs/*/ui, packs/*/seed/canned, public/demo, data/annotations.json, docs/*.md, README.md) by `npm run check:figures`. Run both before handoff.
- Figures allowed on client-facing surfaces: counts of things, clicks, months, and seed-computed amounts labeled example data. Never hours or dollars saved, percentages of the client's time, or any number presented as the client's own.
- No animated counters, spend charts, chat boxes, or stopwatches. The demo shows the work being done and the second month being better than the first.
- Keep each module's `packs/<slug>/STATUS.md` current at every stopping point: built, stubbed, waiting for the pack.

## Design system

- Tokens live in `app/globals.css`. The department hue is `dept` (`bg-dept`, `text-dept`, `bg-dept-soft`, `ring-dept`) and is set by `data-department` on the content column (`components/shell/department-scope.tsx`), so inside a module the default Button is already the department color. Status tones have one meaning each, everywhere: `paid` (green), `risk` (red), `signal` (amber), `lag` (grey-blue), `info` (blue), plus neutral (`bg-muted text-muted-foreground`); violet only for manual split and mail scan. Never use ad-hoc palette classes (`bg-slate-*`, `bg-emerald-*`, `bg-amber-*`, and the like) on a screen.
- Fonts are self-hosted in `app/fonts/` and wired in `app/layout.tsx`: Bricolage Grotesque for headings (h1 to h3 automatically), IBM Plex Sans for reading, IBM Plex Mono for ids, account numbers, invoice numbers, codes, and amounts (`font-mono tabular-nums` or the `Mono` component).
- The shared kit is `components/shell/kit.tsx`: `StatusPill` (tone by meaning, the client's word as text), `Stat` (a big number and its label), `Panel` (a card with a title row; `accent` draws the department rule, on one primary panel per screen), `EmptyState` (the step, then where it starts), `Eyebrow`, `Mono`, `Key`. Screens use these instead of bare bordered divs.
- Every module and screen names the client systems it touches: `systems: SystemRef[]` on the `Module` (and optionally per `Screen`) in `packs/<slug>/module.ts`, rendered as the "Connects to" strip by `components/shell/systems-bar.tsx` and summarised on the Demo home card. Roles are `reads`, `receives`, `replaces`, `unchanged`; the platform is named as the team says it (Monday.com, Yardi, Avid, the parcel database, the legacy property system, the shared drive, provider portals) and the strip always ends with the standing note that nothing is connected in the demo. `lib/registry.test.ts` fails when a module or screen names none.
- Every screen starts with `ScreenHeader` (eyebrow, title, purpose, narration). Every screen key `<module-slug>/<screen-slug>` needs a client entry in `data/annotations.json` with a purpose line and a three-part narration (today, here, protects); `lib/annotations.test.ts` fails the build without it. Narration uses roles, the client's words, no client figures, no em dashes.

## Hosting on Cloudflare

The suite deploys to Cloudflare Workers through `@opennextjs/cloudflare` (`npm run cf:deploy`; `npm run cf:preview` runs the real Workers runtime locally on 8788). `wrangler.jsonc` is the configuration and `worker.ts` the entry point.

- **No filesystem at runtime.** Workers cannot read repo files, so every seed, canned model output and the parcel registry is imported as JSON and bundled: never reintroduce `fs.readFileSync` in a store, a lib used by a route handler, a route handler, or a page. The canned outputs live in one bundled map per pack (`packs/<slug>/seed/canned.json`), rebuilt by `npm run seed:canned`; the individual files under `seed/canned/` remain the readable record. The run sheet page fetches `public/run-sheet.md`, staged from `docs/walkthrough.md` by `scripts/stage-public.ts` (wired to `predev` and `prebuild`).
- **Bundle budget.** The free plan allows 3 MiB compressed; the suite currently uses about 2.2 MiB, most of it seed data. Check with `npx wrangler deploy --dry-run` before adding anything large.
- **One store per viewer.** Cloudflare answers requests from many isolates, so state held in isolate memory does not survive a click. Each browser session is pinned to its own `DemoSession` Durable Object (`worker.ts`), and `lib/session.ts` carries the session id to `lib/store-sessions.ts`, which every pack store uses. `getStore()` and `resetStore()` stay synchronous, so route handlers are unchanged. Without a session (under `next dev` and in the tests) everything shares one store, exactly as before.
- **Optional passphrase.** Setting the `DEMO_PASSPHRASE` secret turns on HTTP basic auth for the whole site; unset, the link is public.
- Build output (`.open-next`, `.wrangler`) is ignored by git, eslint and every hygiene script.

## Pack module contract

A module keeps its rules in `packs/<slug>/lib/` (pure functions, unit tested under `lib/__tests__/`), its store in `packs/<slug>/store.ts`, its screens in `packs/<slug>/ui/`, its deterministic seed generator and JSON in `packs/<slug>/seed/` (canned model outputs under `seed/canned/`), its own identifier rules in `packs/<slug>/markers.json` (shape `{ pack, scope, rules, allow }`, read by `check:markers`), its Playwright specs in `packs/<slug>/e2e/`, its running record in `packs/<slug>/STATUS.md`, route handlers (including `reset`) under `app/api/<department>/<slug>/`, pages under `app/<department>/<slug>/<screen-slug>/`, and generated documents under `public/demo/<slug>/`. Its descriptor `packs/<slug>/module.ts` exports the `Module` object (name, sentence, base, apiBase, resetPath, ordered screens) that `lib/registry.ts` imports; the sidebar, breadcrumb, Demo home, and keyboard navigation read the registry, so a module never builds its own navigation. A module layout is `AnnotationsProvider`, an optional `ModuleBar` for the module's own controls, and `main`; the module root page redirects to `moduleHref`. Screens use `ScreenHeader` with the key `<module-slug>/<screen-slug>`. Modules never import each other, with one exception: `packs/property-owner-lookup` is the shared lookup (registry, normalisation, resolver, owner to entity map, `LookupPanel`) that AP Inbox, the splitter, and later the legal line coder import. Only the utility module has seats (`seats: true`); the seat switch and month stepper never appear on another module. Model steps, where a module has them, read `ANTHROPIC_API_KEY` and `DEMO_MODEL` (default `claude-sonnet-5`) and serve canned output without a key.
